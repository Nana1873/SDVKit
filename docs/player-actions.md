# Player actions in the lab

This matrix lists the everyday keyboard-and-mouse player actions, how to perform each one in a review, and what state read proves its effect. An input result proves only that the input was delivered (see [evidence levels](glossary.md#evidence-levels)). Gaps link to their issues.

"Live" names where the action was verified in a game:
- **script:** [`scripts/acceptance/player-actions.ps1`](../scripts/acceptance/player-actions.ps1) or another [acceptance script](../scripts/acceptance/README.md), in a `single` review on the test save;
- **2.0 release:** the [2.0.0 acceptance](https://github.com/Nana1873/SDVKit/issues/286), where input on split-screen screen 1 opened a menu only on that screen;
- **host, farmhand, screen 1:** the same script with `-Topology network-2 -Role <host|farmhand>` or `-Screen 1` ([#299](https://github.com/Nana1873/SDVKit/issues/299), [#297](https://github.com/Nana1873/SDVKit/issues/297)), which runs the walking, bounded move, hotbar and game-menu rows and, for a role, `stardew_world_act`, watering and the chest transfer through that network role or split-screen screen; **host (setup)** marks host actions that a farmhand run uses as setup.

All input uses SDVKit's [process-local](glossary.md#commands-and-results) input and needs `--allow-input`. A chord (`stardew_input_chord`) holds 1–8 buttons for 1–120 ticks and needs a `uiRevision` from `stardew_menu_get`; one is issued also when no menu is open.

| Change location through a map warp | Chord into the warp tiles listed by `stardew_map_warps_list`, or `stardew_world_move` onto the warp tile; for action doors listed by `stardew_map_actions_list`, `stardew_world_act` with `check` on the door from a neighbouring tile | `runtime.locationId`; a move reports the new `locationId` with `reached: false` | script (Farm to BusStop by chord) | Doors through `check` and warps by `move` are not in the script yet; refused on screens other than 0: `stardew_world_act` needs cursor aim, and those screens run in gamepad mode |
| Warp for setup | `stardew_lab_warp {location,x,y}` (`--allow-fixture-actions`, test save) | Its result and `runtime` | script; host; farmhand | Not on split-screen screens: screens have no fixture tools |

## Roles and screens

Input, menu, inventory, container and world reads, the supported world actions (`stardew_world_interact`, `stardew_world_act`, `stardew_world_move`) and `stardew_container_transfer` work for the `network-2` host and farmhand and for split-screen screens ([MCP startup profiles](mcp.md), [roles and screens](world-interaction.md#roles-and-screens)). Most fixture tools stay single or host only. The rows above were verified live in `single` unless noted. A farmhand run ([#297](https://github.com/Nana1873/SDVKit/issues/297)) also covers the bounded move with its blocked-target refusal, `stardew_world_act` (hoe, sign), watering a plot the host tilled and planted, and both transfer directions through a chest the host placed and filled; the setup steps also ran these tools as the host (`stardew_world_act`, the turn and a transfer deposit), but no host-only run was made. A screen run covers walking, the bounded move from the local farmhand's cabin bed, hotbar and menu input, and two refusals the game gives after accepting the screen binding: `stardew_world_act` in the forced gamepad mode (`worldActionCursorAimUnavailable`) and watering the cabin floor (`worldActionTargetChanged`). Every tool call and every menu, inventory and world read carries the `--role` or `--screen` selection, every runtime read asserts the selected role or screen, inventory reads assert that player's ID, and action results name the topology and role that acted (a screen result names `single` and no role). Such a run is not full acceptance. A role run uses `stardew_fixture_farm` and `stardew_lab_warp` as setup; a screen cannot use fixture tools, so the script walks its farmhand from the cabin bed, measuring the run and the Shift walk from the sub-tile position (about 2.5 and 1 tile for 30 ticks); the hotbar wheel in the world was not rerun there after #294, and `E` on screen 1 left screen 0 without a menu.
